## 3. Subcommands - PARTLY (no `--max-turns`, no `--json`)

Usage string (CLI:18): `usage: exo run [plan] [--detach] [run-plan flags] | exo run --resume <id> | exo approve <id> | exo status [<id>] | exo wait <id> | exo run config [<key> <value>] | exo setup`. `exo --help` prints it; unknown command throws it as a refusal (exit 2).
- All refusals: stderr `exo: <message>`, exit code 2 (CLI:624-633).
- `exo run [plan] [--detach] [flags]`: exit code = run result: 0 passed/landed, 1 stopped/crashed, 2 refused, 3 parked (CLI:496, STATE:10-14, CONTRIB:90). Flags after the plan pass through to `run-plan.mjs` (CLI:299). Accepted run-plan flags (PLAN:31-33, 171-174): `--root <dir> --max-iterations <n> --timeout <minutes> --provider <name> --model <m> --effort <e> --max-budget-usd <x> --max-run-usd <x> --session auto|task|plan --claude <path> --plugin-dir <path> --dry-run`. `--max-run-usd` = cap on the sum of all sessions' `costUsd`; stops with `budget: $X of $Y`, next `raise --max-run-usd, then run exo run again` (PLAN:312-314, 673). `--max-budget-usd` = cap per claude session, passed to claude as `--max-budget-usd`. **`--max-turns` is NOT a flag**: max turns come from each agent file's `maxTurns` frontmatter (`agentMaxTurns`, SESS:269-274; build-task 60 per CONTRIB:101) multiplied by task count for a plan session (SESS:298). An unknown flag fails in `parseFlags` (exit 2, `run-plan: <message>`).
- `exo run --resume <id>`: refuses if no such run (`refused: no run <id> in <root>; exo status lists the runs`), if phase `passed` / `landed` (`refused: run <id> already passed|landed`), if `parked` (`refused: run <id> is parked; use exo approve <id>`), or if the pid is alive and phase non-final (`refused: run <id> is still running (pid N)`) (CLI:407-414). Reuses stored `plan`, `flags`, `detach`. Only looks in `.exo/run/` (not kept). Resume of a `stage: landing` run only reruns the land step (CLI:481). Resume allowed for `stopped`, `crashed`, `refused`, or a non-final phase whose process died.
- `exo approve <id>`: refuses unless phase is `parked` (`refused: run <id> is <phase>, not parked`); marks all open gates approved, then continues like resume (CLI:519-528, 445-448); prints `exo: approved N gate(s) of run <id>; continuing` (not printed when detach). Refused inside Claude Code like `run`.
- `exo status [<id>]` (CLI:536-549): one line per run in `.exo/run/`, sorted by `startedAt`:
  `<id>  <phase>  <plan basename>  pid <pid>[  log <log>][; note]`, where phase reads `<phase>, waiting since <updatedAt>` for stopped/crashed/parked/refused (CLI:530-534). Note is `; exo approve <id>` for parked, or `; process gone, continue with: exo run --resume <id>` when phase is non-final and the pid is dead. Then one `  open gate: <source>: <action> (<reason>)` line per open gate. Exit 0; refuses (2) with `no runs in this checkout` / `no run <id> in this checkout`. **No JSON / machine-readable output exists.** A supervisor should read `.exo/run/<id>/state.json` directly (and `.exo/kept/<id>/state.json` for finished runs) and parse `gates.md`.
- `exo wait <id>` (CLI:573-601): polls every 1 s (`POLL_MS`) until phase is final AND (run is kept OR pid dead); deadline `EXO_WAIT_MS` default 6 h. Prints `exo: run <id> <phase[, waiting since T]>; report <dir>/report.md`; exit 0 for passed/landed, else prints optional `Reason: <reason>` and `Next: <text>` and exits 1; non-final with dead pid: `exo: run <id> <phase>; process gone, continue with: exo run --resume <id>` exit 1; deadline: `exo: run <id> still <phase> at the wait deadline; keep waiting with: ...` exit 124. Unknown id: refusal exit 2.
- Other: `exo setup` (CLI:180-201), `exo run config [<key> <value>]` (CLI:226-253): no args lists merged config as `key = value (run.json|catalog)` and `key <ENV> (<provider>): set|missing`; two args write `~/.config/exo/run.json` (JSON-parsed value, dotted key is written as a literal top-level key, not nested - note `user[key] = value`, CLI:249).

## 4. Phases - CONFIRMED (list exact; one nuance)

`PHASES = ['starting','build','verify','landing','passed','landed','parked','stopped','refused','crashed']` (STATE:5). `FINAL_PHASES = ['passed','landed','parked','stopped','refused','crashed']` (STATE:6). So the claimed list is exact. Non-terminal: starting, build, verify, landing. `updateRun` throws on any other phase (STATE:65).
Transitions:
- `starting` (createRun / resume, CLI:429-430) -> `build` (run-plan `setPhase('build')` after preflight and dry-run, PLAN:249) -> `verify` (PLAN:792, start of Success criterion + review tail).
- run-plan exit code -> phase via `phaseForExit`: 0 `passed`, 2 `refused`, 3 `parked`, anything else `stopped` (STATE:10-14). run-plan also writes the stop phase itself for non-zero exits (PLAN:886), including `stopped` from SIGTERM/SIGINT/SIGHUP (PLAN:285-293).
- If exit 0 and the plan has a `Land:` line: `landing` (phase and stage, CLI:490) -> `landed` (exit 0) or `parked` (exit 3) (CLI:494-496). Without `Land:` the final phase is `passed`.
- `refused` also from CLI-level refusals thrown inside the run (CLI:500-503) and run-plan preflight refusals (exit 2). `crashed` is the default phase (CLI:477) when a non-Refusal exception escapes; the `finally` writes it with exitCode 1. A run whose process is killed hard (kill -9, reboot) leaves a non-final phase with a dead pid: nothing writes `crashed`; `exo status` shows `process gone` (CLI:542-543), and `isAlive(pid)` is the only signal.
- Terminal but resumable: stopped, crashed, refused (via `--resume`; kept dir for refused cannot be resumed since `readState` reads only `.exo/run`), parked (via `approve`). Terminal for good: passed, landed.

## 5. Lock and refusals - CONFIRMED

- Lock file `<root>/.exo/run/lock` holds the run id plus newline (`${id}\n`, STATE:233). Taken with an atomic hard link (`fs.linkSync`) of a temp file (STATE:239). Foreground and `--detach` parent take it; the detached child (`--run-id`) does not (CLI:426) because its parent already holds it under the same id.
- Stale handling: lock is "held" only if holder id differs from mine, its `state.json` exists, phase is not final, and `isAlive(state.pid)` (STATE:224-228). Otherwise it is taken over through a claim-file protocol (`lock.<inode>-<mtime>.<n>` hard links, STATE:203-218, 249-258) and CLI prints `exo: took over the lock of run <id>, whose process is gone` (CLI:437). `releaseLock` removes the lock in `finally` if the holder is this run.
- Lock-held refusal (CLI:435): `exo: refused: run <holder> is still running in this checkout; exo status shows it` exit 2. On refusal a brand-new run dir is deleted again (CLI:434).
- Dirty-tree refusal (CLI:269-275): `exo: refused: uncommitted edits in <space-separated files>; commit them, or discard with git restore --staged --worktree -- <files>`. Only TRACKED changes count (`git status --porcelain --untracked-files=no`, CLI:50-53). In run-plan preflight another message exists: `run-plan: refused: tracked change in the checkout: <file>; commit it first` (PLAN:125). 
- Other refusals worth knowing: `refused: <root> is the checkout exo loads from (...)` (CLI:116-120; a run never edits the exo that drives it, but when root is the plugin checkout with a `Branch:` the run is auto-moved to a worktree, CLI:288-290); plan `Branch:` missing / equals default branch / checkout on another branch (PLAN:118-123); `plan-check --loop fails: ...` (PLAN:136); `no claude on PATH; pass --claude <path>` (SESS:75); `Missing key for <provider>...` (run-config.mjs:66).

  - Permission mode: `dontAsk` + `--permission-prompts none` (CONTRIB:84). Allow rules: Read/Edit/Write under the run root, plugin root and plan dir, the runner's scripts, the plan's Proof/Run/Land gate/Lint/Allow commands, read-only git and inspect commands (SESS:239-258).   - Model/effort: from `--model/--effort` flags, else from the `budget` setting's `build-task` kind (`budgetPin`, PLAN:45-51), doc-only tasks use the `doc-task` kind (PLAN:55, 695); provider `claude` default model `sonnet`, effort `medium` (`lib/run-providers.json`). Budget `off` -> no `--model`/`--effort`. Sandbox (`--settings` JSON with `sandbox.enabled`, network allowlist) is on by default except on win32 or `defaults.sandbox.enabled=false` (SESS:216-237). A `PreToolUse` stall-guard hook is injected through `--settings` for sandboxed task sessions.
- Env (`childEnv`, SESS:320-335): copies `process.env`, then deletes the markers `CLAUDECODE, CLAUDE_PID, CLAUDE_EFFORT, CLAUDE_CODE_CHILD_SESSION, CLAUDE_CODE_ENTRYPOINT, CLAUDE_CODE_EXECPATH, CLAUDE_CODE_MESSAGING_SOCKET, CLAUDE_CODE_MESSAGING_TOKEN, CLAUDE_CODE_SESSION_ATTENDED, CLAUDE_CODE_SESSION_ID` (SESS:30-34); sets `EXO_RUN_TASK=<plan-id>/<n>` (pin), `EXO_RUN_HANDOFF`, `EXO_RUN_REPAIR`; `EXO_RUN` and `EXO_RUN_DIR` are inherited from exo-cli (CLI:298). **ANTHROPIC_API_KEY**: deleted only when the provider is not `claude` (SESS:330); with provider `claude` an inherited `ANTHROPIC_API_KEY` is passed through, so whether a run bills the API or the logged-in subscription depends on the env exo run was started with. Other providers (deepseek, zai) add `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN` (from `~/.config/exo/keys.env`), model vars. `CLAUDE_CODE_EFFORT_LEVEL` is set from the pinned effort when non-null (SESS:333); `FORCE_PROMPT_CACHING_5M=1` when `promptCacheTtl` is `5m` (default). Git is told via `GIT_CONFIG_*` to use `core.hooksPath=session-git-hooks` so the session cannot commit (SESS:305-318). Process group: detached; timeout (`--timeout`, default 60 min) sends SIGTERM to the group, SIGKILL after 5 s (SESS:412-419).
- Stream parsing: `parseStream(text)` (SESS:81-137) JSON-parses each line of stdout+stderr and silently skips non-JSON lines (82-89). Event types read:
  ```js
  const init = events.find((event) => event.type === 'system' && event.subtype === 'init') ?? null;   // :90  -> model, session_id, plugins, plugin_errors
  const results = events.filter((event) => event.type === 'result');                                  // :91
  const ruleDenied = new Set(events.filter((event) => event.type === 'system' && event.subtype === 'permission_denied').map((event) => event.tool_use_id)); // :99
  const calledIds = ... events.filter((event) => event.type === 'assistant') ... block.type === 'tool_use' // :100
  events.filter((event) => event.type === 'assistant' && event.message?.usage) // :107  tokens/cache
  hooks: events.filter((event) => event.type === 'system' && event.subtype === 'hook_started').length // :133
  ```
  From `result`: `permission_denials`, `usage.output_tokens`, `num_turns`, `total_cost_usd` (cost = last result's), `subtype`, `result` (text), `session_id` (:94-125). The final reply text's LAST non-empty line is the task status line (`Task <n>: BLOCKED ...`, `PLAN DRIFT`, `HANDOFF`, etc., PLAN:603,699,719-726). `init` is also checked live: if the loaded exo is missing/wrong path the session is SIGKILLed (`refuseInit`/`exoError`, SESS:147-155, 392-395) and the run stops `exo not loaded: ...`.
  The only result `subtype` exo acts on is `error_max_turns` (PLAN:588, 714) -> `task <n> blocked: hit --max-turns N` and partial work saved to `.exo/carry/task<n>-partial.patch`. A timeout is tracked by the spawner (`timedOut`).
- **Limit / rate-limit / overload detection: NONE.** `grep -riE "rate_limit|rate limit|usage limit|resets|429|overloaded|is_error|api_retry"` over `skills/ lib/ hooks/ agents/` finds nothing in the run path. The only `rate_limits`/`resets_at` hits are `lib/statusline.mjs` (it reads the status-line payload's `rate_limits.five_hour` / `seven_day`, not the run). So when claude hits a usage limit, 429 or overload: the session just ends, the result text (or "no result event (exit N)", PLAN:603,699) becomes `last`, `land-task` is tried, the attempt is recorded as a failed attempt with a fingerprint; a second identical failure gives stop `no progress on task <n> in <k> iterations` and the `attemptCap` (default 4, `lib/run-providers.json` defaults) gives `attempt cap 4 reached` (PLAN:757-770). Final phase `stopped`, exit 1, reason indistinguishable from a real failure. Design impact: an app must itself detect rate limits (read the raw stream-json in `iter-*.log` for `rate_limit_event`/`is_error` result events, or poll the usage endpoint) and use `exo run --resume <id>` after the reset; exo will not wait for resets. There is no built-in sleep/retry-after-reset. (The only waiting code is `sayIdle`, a log line after a sleep gap, PLAN:515-518, `EXO_IDLE_MS`.)

## 10. Parked runs and gates.md - CONFIRMED

- Parked = a stop that needs a person: run-plan exit 3 (a session's `Task <n>: PARKED` marker via `<EXO_RUN_DIR>/parked`, or a rebase conflict at review start) -> phase `parked`, stage `build` (CONTRIB:87,90, PLAN:399-407,856-862); or `land-run.mjs` returned parked (phase `parked`, stage `landing`, CLI:341,494-496).
- File `<root>/.exo/run/<id>/gates.md`, one line per gate, regex `^- (open|approved|used): ([^:]+): (.*) \(([^()]*)\)$` (STATE:80). Format: `- <status>: <source>: <action> (<reason>)`. Example the code produces (PLAN:860): `- open: land: rebase feat/x onto main yourself in /path/to/worktree (rebase conflict)`. `source` is a short label (e.g. `land`), `action` is a one-line command/action text (newlines collapsed), `reason` has parentheses/newlines stripped (STATE:98-106). Duplicate open gate with same source+action is not re-added.
- Status values: `open` -> (`exo approve`) `approved` -> (`takeApproved`, when the gated action is performed) `used` (STATE:108-123).
- `exo approve <id>` (CLI:519-528, 445-448): requires phase `parked`; flips ALL open gates to `approved` (no per-gate selection, prints count), then continues like `--resume` by stage: stage `build` reruns run-plan (it resumes from landed `Plan-task:` commits), stage `landing` reruns only `land-run` (CLI:481). `--resume` refuses `parked` and `landed`. So "approve" means "the person has done/consented to the gated action" - for the rebase gate the person must rebase by hand first. What land-run gates look like (push, merge etc.) is in `skills/build/scripts/land-run.mjs` (not read in detail; it opens gates via `openGate` and returns `{phase:'parked', gate: reason}`, land-run.mjs:105).
- `exo status` lists open gates as `  open gate: <source>: <action> (<reason>)`; `report.md` lists up to 4 open gates.

## 11. Other facts a supervising app must know

- Worktrees: `buildRun` (CLI:282-324). If the run's checkout is the one the plugin loads from (pointer realpath == root) AND the plan has `Branch:`, the run is done in a worktree `<root>/.worktrees/<branch with "/" replaced by "-">` (`git worktree add [-b] ...`, CLI:68-81; refuses if the branch is checked out in the main checkout) and run-plan gets `--root <worktree>`. Otherwise the run uses the checkout itself and does `git switch <Branch>` (creating it from the default branch if missing, CLI:55-66) - this changes the user's checked-out branch. `env=copy` setting copies ignored `.env*` files into the new worktree (CLI:79,83-98). Before a real run, with a remote: `git fetch --prune`, fast-forwards the local default branch to origin, prunes merged branches whose upstream is gone (CLI:136-172, 285-295; skipped for `--dry-run`/`--help`).
- Run branch naming: no exo-generated names. The branch is the plan's `## Plan basis` `Branch:` line (required; must not be the default branch, PLAN:117-123). Each landed task is a commit with a `Plan-task:` trailer (CONTRIB:84-85, `planTaskTrailer`); resume reads landed tasks from those trailers.
- `Land:` plan line (`frameOf(...).land`): none -> run ends `passed` and nothing is merged ("review branch X, then push it or open a pull request", PLAN:877). `Land: local` -> `land-run.mjs` squashes the branch onto the default branch as the plan's `Commit:` message (project CLAUDE.md of exo itself; mode set in `land-run.mjs`); `Land: pr` -> push + PR (result has `prUrl`, `pushed`, CLI:341,372). Modes are read in `land-run.mjs` (not read in detail); report.md shows `Land: <mode|none>`.
- report.md (CLI:354-381): first up to 15 lines: `# exo run <id>`, `Phase: <phase>`, `Reason: <one line>` (only for refused/stopped/crashed), `Land: <local|pr|none>`, `Branch: <branch|none>`, `Landed: <short..short|none>` (commit range), `Pushed: <prUrl|pushed|none>`, `Open gates: <n>` plus up to 4 `- <source>: <action> (<reason>)`, `Decisions: <n>` (count in decisions.md), `Cleanup: <...|none>`; then the whole text of `denied.txt` (commands refused by permission rules). Written at start (phase `starting`, also at resume), and at each final phase.
- Notifications: `osascript -e display notification "exo run <id>: <phase>" with title "exo"` at every final phase, errors ignored (CLI:393-396, 513). macOS only; there is no webhook/other notification, so an app should watch `state.json` itself. On macOS the run process also spawns `caffeinate -i -w <pid>` (CLI:469-474).
- stdout of run-plan: lines `[mm:ss] <event>` (run start, task start, landed, run done) then a <=6-line summary ending `Details: <dir>/summary.txt`; last line of summary.txt is `run-plan: stop: <reason>` (CONTRIB:86-87; stop reasons list at CONTRIB:87). A supervisor's progress source is `state.json` (`task`, `landed`, `total`) and `progress.md`.
- Env vars: `EXO_RUN` (run id) and `EXO_RUN_DIR` (the `.exo/run/<id>` dir) set by exo-cli for run-plan and inherited by claude sessions (CLI:298); `EXO_RUN_TASK=<plan-id>/<n>` (land-task pin), `EXO_RUN_HANDOFF`, `EXO_RUN_REPAIR`, `EXO_DROPS` (CONTRIB:26,30). `EXO_RUN_DIR` set also switches the `run-no-wait` hook on (a question to the user is denied; decisions go to `decisions.md`, CONTRIB:94). Tunables: `EXO_WAIT_MS` (wait deadline, default 6 h), `EXO_IDLE_MS` (60 s), `EXO_APP_READY_MS` (120 s), `EXO_REVIEW_TIMEOUT_MS`, `EXO_GATE_TIMEOUT_MS` (1 800 000), `EXO_TBENCH_POLL_MS`, `EXO_HOST` (codex). Config: `~/.config/exo/run.json` (deep-merged over `lib/run-providers.json`: `efforts`, `defaults.{provider,effort,contextLimit=100000,promptCacheTtl=5m,turnOneCacheWriteWarn=20000,attemptCap=4,sandbox.{enabled,allowedDomains}}`, `providers`), `~/.config/exo/keys.env`.
- Context guard: detached run sessions are denied tools past `defaults.contextLimit` (100000 tokens hard, 60% soft) and told to hand off (`Task <n>: HANDOFF`, handoff file under the scratch folder); run continues in a new session (CONTRIB:98, PLAN:719-723).
- The run only counts a task landed through `land-task.mjs` (sessions are blocked from `git commit`); a run needs plan frame fields (`Branch:`, `Land:`, `Commit:`, `Success criterion`, per-task `Files:`/`Proof:`) and `plan-check --loop --run` must pass (PLAN:126-137).
